# صيانة السيرفر — مساحة القرص

القرص الممتلئ يوقف قاعدة البيانات. ثلاث أشياء تملأه مع الوقت: صور Docker
القديمة (كل تحديث يسحب صوراً جديدة)، سجلات الحاويات، والنسخ الاحتياطية المحلية.

## 1) إعداد لمرة وحدة: تحديد حجم سجلات Docker

```bash
sudo tee /etc/docker/daemon.json >/dev/null <<'JSON'
{
  "log-driver": "local",
  "log-opts": { "max-size": "20m", "max-file": "5" }
}
JSON
sudo systemctl restart docker
cd /opt/influenceos && docker compose up -d   # حتى تأخذ الحاويات الإعداد الجديد
```

> إذا كان الملف `/etc/docker/daemon.json` موجوداً وفيه إعدادات ثانية، أضف
> المفتاحين بدل استبدال الملف.

## 2) تنظيف أسبوعي تلقائي

```bash
crontab -e
# كل يوم أحد الساعة 4 الفجر:
0 4 * * 0  cd /opt/influenceos && scripts/server-maintenance.sh >> /var/log/influenceos-maintenance.log 2>&1
```

السكربت يحذف فقط صور Docker غير المستخدمة والأقدم من أسبوع، ولا يلمس قاعدة
البيانات ولا الملفات المرفوعة ولا الحاويات الشغّالة.

## 3) المراقبة من داخل البرنامج

**الإعدادات ← المنصة ← حالة المكوّنات ← Disk** تعرض نسبة الامتلاء والمساحة
الفارغة: أصفر عند 85% وأحمر عند 95%.

## 4) النسخ الاحتياطية المحلية

تُحفظ في `/var/backups/influenceos` (أو `BACKUP_DIR`). إذا كان القرص صغيراً،
فعّل النسخة خارج السيرفر (انظر `docs/BACKUPS_AR.md`) وقلّل
`BACKUP_RETENTION_DAILY`.

## 5) تنبيهات بدون أدوات إضافية

- **داخل البرنامج:** كل مدير (Admin) يصله إشعار إذا فشلت كل مزامنات منصة
  (مثل انستغرام) خلال آخر 24 ساعة، أو إذا توقفت مهمة خلفية بعد كل المحاولات.
  يظهر الخطأ أيضاً في **الإعدادات ← التكاملات**.
- **إذا توقف السيرفر كله:** أنشئ فحصاً مجانياً في موقع مثل Healthchecks.io
  (كل 30 دقيقة، مهلة 30 دقيقة)، وضع رابطه في `.env`:

  ```bash
  HEALTHCHECK_PING_URL=https://hc-ping.com/xxxxxxxx
  ```

  الـ worker يرسل له إشارة بعد كل دورة. إذا انقطعت الإشارات يصلك بريد منهم.
  (يحتاج تمرير المتغير إلى حاوية الـ worker في ملف compose — راجعني قبل
  تعديل ملف الإنتاج.)

## 6) مفتاح تشفير منفصل (اختياري)

مفاتيح المنصات المحفوظة من شاشة التكاملات مشفّرة بمفتاح مشتق من
`AUTH_SECRET`. لفصلها:

1. أضف `ENCRYPTION_KEY` (32 حرفاً على الأقل) للـ api والـ worker وأعد تشغيلهما.
2. نفّذ مرة واحدة (بدون تغيير `AUTH_SECRET`):
   `docker compose exec api pnpm --filter @influenceos/api exec tsx src/scripts/reseal.ts`

## 7) صفحة توثيق الـ API

صفحة `/api/docs` مغلقة في الإنتاج افتراضياً (تكشف كل مسارات النظام). لفتحها
مؤقتاً ضع `API_DOCS=on`.

## 8) التحديث إلى نسخة محددة والرجوع عنها

بدلاً من `docker compose pull && docker compose up -d` (التي تأخذ آخر نسخة):

```bash
scripts/deploy-sha.sh <رقم الـ commit>   # نسخة محددة مرّت بالاختبارات في CI
scripts/deploy-sha.sh --rollback          # الرجوع للنسخة السابقة
scripts/deploy-sha.sh --status            # ما الذي يعمل الآن وسجل التحديثات
```

السكربت يأخذ نسخة احتياطية من قاعدة البيانات أولاً، يثبّت رقم النسخة في `.env`
حتى لا تتغير بعد إعادة التشغيل، يتأكد أن البرنامج اشتغل، ويحذف الصور القديمة
(يُبقي آخر 3 للرجوع السريع). الرجوع لا يُرجع قاعدة البيانات.
